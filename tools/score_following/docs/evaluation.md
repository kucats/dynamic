# 評価と限界

## 正解ラベル

サンプルのlabels.jsonと同じ、音声時計の配列です。単旋律・重なりなし。

```json
[
 {"event_id":"n000","onset_s":0.240,"offset_s":0.640},
 {"event_id":"n001","onset_s":0.740,"offset_s":1.140}
]
```

反復を実演した場合は同じevent_idを複数の音声区間に記録できます。譜面自体に反復を展開した場合は別occurrenceのevent_idを使います。time=0はWAVの最初のsample。無音区間を削って時間を詰めないでください。録音許可のないデータや原譜PDFをcommitしません。ラベルを追従器へ供給せず、推定traceを完成させてから比較します。

## 8シナリオ

clean、noise(標準偏差0.008)、tempo倍率0.7/1.3、28cent detune、2秒停止、途中への吹き直し＋skip、9番目の音からの開始（index=8）。16音のオリジナル合成フレーズです。独立の実録音の代用ではありません。seed=91723でnoiseを生成します。音色は基音＋2/3倍音と短いattack/releaseであり、実楽器の複雑なアタック・息・強弱を再現していません。

指標:

- exact_frame_accuracy: 正解の発音区間内にある全20msフレームのevent_id一致率。null/未捕捉も誤りに含む。立ち上がり遅延を含む。
- post_attack_200ms_accuracy: 同じ区間から最初の200msだけ評価時に除外した一致率。推定自体を遅らせているわけではない。上の指標と併記する。
- confirmed_precisionとconfirmed_coverage: confirmedだったフレームの正解率と、そもそもconfirmedを返した割合。precisionだけを抜き出さない。
- per_note_first_correct_ms: 区間内で初めて正しいevent_idが出るまでの時間。未捕捉はnull。正解が一瞬出ただけでも計上するので、安定ロック時間ではない。
- hop_compute_p95_ms / real_time_factor: CPU処理のみ。回線/端末描画遅延・多数セッションの実測ではない。

実行結果のjsonとtraceは生成コマンドで再現可能です。候補の誤りもすべてtraceへ残し、都合のよい音だけ抽出しません。

## 既知の性能境界

DSPは40〜1800Hzのfundamentalを探索。標準A4=440Hz、options.a4_hzで変更可能。APIのMIDI入力範囲はこれより広いですが、音声backendの有効範囲が同じとは限りません。trailing window128msを使い、音高変化は4回の20ms hopで丸め音高が安定してから確定します。同音再アタックは短いenergy dip後に120ms同音が維持されたことを確認します。したがって極端に速い音符、非常に弱いアタック、低い基音は別途検証が必要です。単旋律と低い背景音を前提とし、chroma和音追従・楽器分離・OMRは含みません。

beamは音符単位で同じ位置の最良仮説を残します。完全なテンポ分布/HMM後方確率/較正確率は計算しません。複数の同音フレーズは初音だけでは一意に決まらず、先頭数音が別候補のままになることがあります。吹き直しは複数音の証拠を待つため、瞬時の再捕捉を保証しません。移動量の小さなskipと全域のrestart seedが対象で、複雑な反復意味論は事前展開した譜面の責務です。

連続する無音からは、演奏停止と休符の経過を一意に区別できません。v1は長休符を勝手に数えて次小節へ送らず、直前位置でholdingへ移します。指揮や他パートを利用した休符追従は別の推定問題として扱います。
