# DYNAMIC 譜読み 再現ランブック（Claude Code 向け）

パート譜のPDFを入力に、**音符ごとの記譜ドレミ（またはCDEFGAH＋ポジション）・音価・小節番号**を持つ譜読みデータを作り、
`public/reader/`（閲覧・試聴・通し再生）と印刷用PDFまで仕上げる手順です。
今回（ドボルザーク8番のホルン2番・3番、トロンボーン1番）で実際に通った経路と、途中で失敗して変えた点をそのまま書いています。

---

## 0. 全体像

```
原譜PDF ──pdftoppm──▶ ページ画像(300/340dpi) ──cand.py──▶ 符頭の候補（下書き）
                                                   │
             ┌─────────────── サブエージェント × ページ数（並列） ───────────────┐
             │ ① 音高・臨時記号・キュー除外 → work/final_pNN.json                 │
             │ ② 音価・小節内位置・拍子/テンポ/管の指定（同じエージェントに続けて） │
             │ ③ 小節番号（小節線の自動検出を直して全小節に番号）→ work/bars_pNN.json│
             └───────────────────────────────────────────────────────────────┘
                                                   │  メイン：要確認箇所の目視、ページ間の小節番号の整合
                                                   ▼
        project/<作曲者>/<作品>/<パート>/dynamic/{part.json, pages/notes_pNN.json, pages/bars_pNN.json}
                                                   │ build_reader.py
                                                   ▼
        public/reader/data/<id>.json ──▶ 閲覧アプリ ──render_pdfs.py──▶ A3のPDF
```

要点は「**機械は位置と下書きだけ、音の判断はページ単位のサブエージェント、検算はスクリプト**」という分担です。
五線・符頭の完全自動認識（OMR）は、この版の譜面では白抜きの音符・加線・連桁の上の音・キューの判別で失敗が多く、主役にしませんでした。

## 1. 使ったソフトウェア

| 用途 | ソフト | 入れ方 |
| --- | --- | --- |
| PDF → ページ画像、ページ数確認 | Poppler（`pdftoppm`, `pdfinfo`） | `apt install poppler-utils` / `brew install poppler` |
| 画像処理（五線・符頭・小節線の検出、切り出し） | Python 3.11+、OpenCV、NumPy、Pillow | `pip install opencv-python-headless numpy pillow` |
| ブラウザでの表示確認・自動テスト・PDF出力 | Playwright ＋ Chromium（ヘッドレス） | `pip install playwright && playwright install chromium` |
| JavaScriptの構文チェック | Node.js（`node --check`） | 任意のLTS |
| ローカル配信 | `python3 -m http.server` | 標準 |
| 検算 | `tools/dynamic/check_rhythm.py`、`validate_reader.py`、`python3 -m unittest` | リポジトリ内 |
| 画像を「見る」 | Claude Code の Read ツール（PNGを開くと画像として読める） | — |

Claude Code 側で使った機能：**Agent（サブエージェント）**、**SendMessage（同じサブエージェントに追加の指示・中断からの再開）**、Read（画像）、Bash、Write/Edit。

## 2. 準備（最初にClaude Codeへ渡すプロンプト）

> このリポジトリ（dynamic）で、添付のパート譜PDF `<ファイル名>` の譜読みデータを作りたい。
> まず `tools/dynamic/RUNBOOK.md` と `tools/dynamic/README.md` を読んで手順を把握して。
> 次に PDF の全ページを 40dpi で描画して1枚のサムネイル一覧にし、**どのページがどのパート・どの楽章か**を表にして見せて。
> 対象は「<パート名> の <楽章>」。元PDFの SHA-256 も計算して控えておいて。

ここで確認すること（今回の実例）：
- ホルンのPDFは4パート分が入っていて、**ユーザーの言う「p13」は2番の3楽章**、3番の3楽章は20ページだった → 必ずページ一覧で確認する。
- トロンボーンのPDFは Tb1・Tb2・Tb3・Tuba 入り。Tb1 は 1〜5ページ（II・III楽章はTacet）。

## 3. ページ画像と下書き

> 対象ページを `pdftoppm -r 300 -gray` で `work/pNN.png` に描画して、`tools/dynamic/common.py` の `staves()` で
> 各ページの五線の段数と線の間隔を出して。線の間隔が 24〜28px になる解像度にしたい。

- ホルン（A4相当）は **300dpi で線間隔 ≈26px**。トロンボーンは版が小さく 300dpi だと 23px だったので **340dpi** にした。
  以降のしきい値（符頭の大きさ、切り出し余白）はこの間隔が前提。
- 段数がページの見た目と合わないときは要注意（今回、ページ最上段や楽章見出しの段が落ちた例、同じ段を2つと数えた例があった。
  `staves()` は複数のx位置で検出して統合するようにしてある）。

> `python3 tools/dynamic/cand.py <ページ番号...>` で符頭の候補と重ね描き（work/ov_pNN.png）を作って、1ページだけ縮小して見せて。

候補は**ヒント**です。塗りつぶしの符頭はある程度拾えますが、白抜き（2分・全音符）、加線上の音、連桁に接した音は落ちます。
逆に強弱記号の文字や休符も混ざります。

## 4. ページごとのサブエージェント（音高）

**プロンプト（メイン → Claude Code）**

> サブエージェントを**1ページに1体**、並列で起動して。種類は general-purpose。
> それぞれに `tools/dynamic/prompts/01_transcribe_page.md` を読ませて PAGE を指定し、ページの位置づけを一言添えて
> （例：「PAGE = 9、ホルン2番の最初のページ、題名と第1楽章」）。
> 出力は `work/final_pNN.json` と自分の確認画像だけ。終わったら要確認の一覧を報告させて。

各サブエージェントがすること（01の中身）：
1. `zoom.py PAGE SYS` で段ごとの拡大図を作る。左端に **音高ガイド**（ト音記号の音名／(ヘ音)／[アルト]）、上に**ページ座標の目盛り**が入る。
2. 必要なら 500〜800px 幅でさらに拡大して、符頭ごとに線か間かを読む。
3. 臨時記号の持続（小節内・タイで持ち越し・♮で解除）と調号を適用して、**記譜音**を `F#4` 形式で書く。
4. **キュー（他楽器の小さい音符）を除外**する。判断材料は、符頭が小さい／楽器名の表記（Viol.I, Trbe, Timp., Cor.I…）／同じ小節に全休符がある。
5. `check.py PAGE` で読み取り結果を原譜に重ね描きし、全ページ分を目で見直す。

**トロンボーンは1回で音高・リズム・小節番号まで**頼んだ（`prompts/11_trombone_page.md`）。アルト記号・調号（G durの♯）・音部記号の切り替えを明記している。

### メインがやる目視確認
サブエージェントの報告にある要確認箇所と、自分で気になった箇所を拡大して確認します。

> ページ11の300〜303小節あたりを、原譜から切り出して拡大して見せて（♭が本当に付いているか）。

今回ここで見つかったもの：
- ホルン3番 207〜215小節：私（メイン）の最初の読みではキューを吹く音として入れていた → **独立の検証用サブエージェント**が指摘し、符頭の大きさの比較で確定して除外。
- ホルン2番 2楽章45小節頭：キューだったのでサブエージェント自身が後の段階で除外。
- 以前の別監査とは逆の判断（3楽章G部分は「Timp.」のキュー）を、表記と全休符で確認。

### 独立の検証（重要な成果物に）
読み取った本人とは別のサブエージェントに、一覧と原譜だけを渡して照合させます。

> 新しい general-purpose サブエージェントで、`work/pNN.png` と、私が作った音の一覧（小節・音高・音価・タイ）を照合させて。
> 1音ずつ、線/間・臨時記号・音価・小節・タイを確認し、**食い違いだけ**を、確信度つきで報告させて。見落とし・キューの混入も探させて。
> ファイルは書き換えないこと。

## 5. リズム（同じサブエージェントに続けて）

> 各ページのサブエージェントに SendMessage で続きを頼んで：`prompts/02_rhythm_timing.md` を読んで同じページで実行。
> 「ページ先頭で有効な拍子も meters に入れること」と添えて。

- 各音に `dur`（全音符=1の分数。3連の8分は `1/12`）と `off`（小節頭からの位置）を追加。
- ページの `meta`：拍子、テンポ（メトロノーム記号）、管の指定（in F / in D / muta in C …）、反復（D.S.、⊕、1番2番かっこ）。
- `check_rhythm.py PAGE` で「小節からはみ出す音」「重なる音」を0件にする（休符は見ていないので短い小節はOK）。

同じエージェントに続けて頼むのは、**ページの読み取り内容を覚えている**ので速く、正確だからです。

## 6. 小節番号（全小節）

> `barlines.py` で各段の小節線を検出して、音符の小節番号から自動で番号を推定した `work/bars_auto_pNN.json` を作って。
> そのあと各ページのサブエージェントに `prompts/03_bar_numbers.md` を実行させて `work/bars_pNN.json` を作らせて。

- 自動検出は**符幹（音符の棒）を小節線と誤認**しやすく、多小節休みが続く所は番号が決まらないので、サブエージェントに直させる。
- 多小節休みは `"61–64"` のように範囲で書く。
- 検算：**全音符が、自分の小節番号を持つ区間に入っているか**（validate_reader.py が見る）。

### ページ間・パート間の番号の食い違い
印刷された番号がないパートでは、ページごとに数えると**ずれることがある**。今回：
- トロンボーン1番 4楽章：3ページ目の数え方では2番かっこ=90、4ページ目は E=93 から始まっていた。
- 解決：**別パート（ホルン）に印刷された番号**（C=59, D=75, E=93, 最後=389）に合わせ、ずれ方（54小節目以降+1、84小節目以降+2）を記録して補正。
→ メインが複数ページの報告を突き合わせて判断する。

## 7. 採用データの配置とパート設定

```
project/<作曲者>/<作品>/<パート>/dynamic/
  part.json               id・タイトル・元PDFのSHA-256・ページ・楽章（拍子・テンポ・D.S.の順序）・管・状態と注意書き
  pages/notes_pNN.json    work/final_pNN.json を採用したもの（PDFのページ番号で2桁）
  pages/bars_pNN.json     work/bars_pNN.json を採用したもの
```

`part.json` の要点：
- `movements[].tempos`：小節ごとの4分音符のBPM。記号がない meno mosso 等は目安の値にして、そのことを `limitations` に書く。
- `movements[].sequence`：D.S. などの再生順（例：3楽章 `[[1,180],[2,86],[181,231]]`）。
- `splits`：1ページに2つの楽章がある場合の境目の段。
- ホルンは `default_horn_key`（F など）と、音ごとの `horn_key`。トロンボーンは `"instrument": "trombone"`（CDEFGAH＋ポジション）、`"dpi": 340`。

## 8. 生成と検証

> `python3 tools/dynamic/build_reader.py --pdf <元PDF> --work work project/.../dynamic` を実行して、
> `python3 tools/dynamic/validate_reader.py` と `python3 -m unittest discover -s tests` と `node --check public/reader/app.js` を通して。
> 次に `python3 -m http.server 8765 -d public` を起動し、Playwright で閲覧ページを開いて
> ①デスクトップ幅と iPhone 幅でスクリーンショット ②音符をクリックして上部の表示を確認 ③小節ジャンプ ④再生して小節表示が進むか
> ⑤ページエラーが0件か、を確認して。最後に `render_pdfs.py` でPDFを作り、代表ページを画像にして見せて。

| 検証 | 方法 | 合格の基準 |
| --- | --- | --- |
| 音高・キュー | サブエージェントの `check.py` 重ね描き＋メインの拡大確認＋独立検証エージェント | 食い違い0、要確認は `uncertain` に記録して画面で赤い点線枠 |
| 臨時記号 | 拡大図で♭♯♮を1つずつ（ユーザー指摘の重点） | 小節内持続・タイの持ち越し・調号を適用済み |
| 音価 | `check_rhythm.py` | はみ出し・重なり0件 |
| 小節番号 | `bars_overlay.py` の確認図、`validate_reader.py` | 全音符が正しい番号の区間内、ラベルが増加順 |
| 再生タイムライン | `validate_reader.py`（全音符の小節がタイムラインにある）、ブラウザで `timeline()` の音数と長さを表示 | 楽章ごとの音数がデータと一致（D.S.分は重複して増える） |
| 表示 | Playwright のスクリーンショット（1440px・390px）、PDFを `pdftoppm` で画像化して目視 | ラベルが重ならない、線で音符とつながる、ページエラー0 |
| 公開物の安全 | `validate_catalog.py`・`validate_reader.py` | 元PDF・ページ全体の画像・ローカルパスが public/ に無い |
| 音程計算 | `tests/test_dynamic_reader.py` | 移調と綴り（F管、D管、F管読み、♯・♭）が正しい |

**確認していないこと**も明記する：合成音を耳で聞いての確認、第三者（人）による監査。

## 9. 表示ルール（今回ユーザーと詰めたもの）

- 字は**すべて同じ大きさ**。音の大小で字の大きさを変えない（変えると読みにくいという指摘）。
- 音符と字は**細い線でつなぐ**。字が横にずれても対応が分かる。
- 1列に入らない所は**音の高い方を上段、低い方を下段（少し小さい字）**。同じ高さが続く所は交互。
- 小節番号は全小節（茶色）、多小節休みは範囲。
- ホルン：記譜ドレミ（青）＋任意でF管読み（橙）・実音（緑）、オクターブは小さい数字（ド⁴＝中央のド）。旧記譜のヘ音記号は ※。
- トロンボーン：CDEFGAH（H＝シ、B♭）＋オクターブ、B♭テナーの基本ポジションを別の色（F＝1 など）。

## 10. 試行錯誤で分かったこと（時間を減らすコツ）

1. **最初にページとパートの対応を表で確認**。指示のページ番号がずれていることがある。
2. **符頭の自動認識に頼らない**。下書き（候補）＋座標の目盛り＋音高ガイド付き拡大図を用意し、判断はサブエージェントに。
3. **1ページ＝1サブエージェント、同じエージェントに段階的に追加指示**（音高 → リズム → 小節番号）。文脈が残るので速い。
4. サブエージェントには**早めにファイルを書かせる**。今回、利用上限で5体中5体が途中停止し、書き出し前だったものはやり直しになった。
   SendMessage で同じエージェントを再開できる（止まった時点の文脈から続く）。
5. **キューの混入が一番多い誤り**。「楽器名表記・小さい符頭・同じ小節の全休符」の3点を必ず指示に入れる。
6. **臨時記号の持続**（小節内・タイ）と**調号**は明示的に指示する。
7. 旧記譜のヘ音記号（ホルン）は1オクターブ下に書かれている。前後の自然倍音の流れで判断する。
8. 小節線の自動検出は符幹を拾う → 小節番号は必ずエージェントに確認させる。印刷番号のないパートは他パートの印刷番号と突き合わせる。
9. 生成物は**データ（JSON）とレンダラ（HTML/JS）を分ける**。表示の改善（字の配置など）はJSだけ直せば全パートとPDFに反映される。
10. 目安：1ページの音高読み 4〜7分（トークン 12〜17万程度）、リズム追加 2〜5分、小節番号 2〜4分。5〜7ページのパートで並列なら30〜40分。

## 10b. ナブッコ序曲（トロンボーン2番）で追加したこと

- 指示は `prompts/21_nabucco_trombone_page.md`（ヘ音記号、頻繁な調号の変更、B/B♭/H と ♯ の重点確認）。
- **小節反復記号（％）**：その小節の音を `"sim": true` で書き出し、記号の下に並べる（画面では薄い字・点線枠、再生にも含める）。
- **印刷番号のない曲**：各サブエージェントは**ページ内の通し番号**（ページ先頭＝1、多小節休みは長さ分）で書き、
  `meta.local_bar_count` を報告させる。メインがページごとのオフセット（前ページまでの小節数の合計）を足して通し番号にする。
- テンポ記号だけでメトロノーム記号がない曲は、目安のBPMを `part.json` に入れて、そのことを注意書きに書く。

## 11. 一括で頼むときのプロンプト（コピー用）

> 添付の `<PDF>` の `<パート>`（ページ `<a〜b>`、楽章 `<…>`）を、このリポジトリの DYNAMIC 形式で譜読みして。
> 手順は `tools/dynamic/RUNBOOK.md` に従う。
> 1. ページ一覧で対象ページを確認し、元PDFのSHA-256を控える。線間隔が約26pxになる解像度でページを描画し、`cand.py` で候補を作る。
> 2. 1ページ1体のサブエージェントを並列起動し、`prompts/01`（トロンボーンは `prompts/11`）を実行させる。読み取ったらすぐファイルに書かせる。
> 3. 同じエージェントに `prompts/02`（リズム）と `prompts/03`（小節番号。先に `bars_auto` を作る）を続けて実行させる。
> 4. 要確認箇所はメインが拡大して確認。ページ間の小節番号を突き合わせ、ずれは印刷番号（他パートを含む）で補正して記録する。
> 5. 独立の検証サブエージェントに主要な楽章を照合させ、指摘を反映する。
> 6. `project/.../dynamic/` にデータと `part.json`（テンポ・D.S.・管・注意書き）を置き、`build_reader.py` → `validate_reader.py` → unittest → ブラウザ確認 → `render_pdfs.py`。
> 7. 表示は：字は同じ大きさ、音符と線でつなぐ、詰まった所は高い音を上段・低い音を下段（小さめ）、全小節に小節番号。
>    ホルンは記譜ドレミ、トロンボーンは CDEFGAH（H＝シ）＋オクターブ小さく＋ポジションを別の色。
> 8. 最後に、単体PDFと、中間ファイル（候補・拡大図・照合図・作業版JSON）のzipを渡して。未確認の点（耳での確認、第三者監査）も書いて。
