# Execution Plans

Use a living execution plan when work spans multiple material steps, sessions, repositories, migrations, uncertain design, production-sensitive changes, or difficult validation.

A plan is not a frozen proposal. Keep these sections current as work proceeds:

- progress with timestamps and exact refs;
- discoveries and unexpected constraints;
- decisions and rationale;
- validation evidence;
- remaining work and recovery instructions.

Store active plans in this directory using `YYYY-MM-DD-short-title.md`. Start from `TEMPLATE.md`. Link the plan from the tracking Issue and pull request.

Small, obvious, single-PR work does not need a separate plan when the Issue already contains sufficient detail.
