# 0002 — DYNAMIC reader app as the public site

- **Status:** proposed (user-directed, 2026-09-24)
- **Context:** The owner asked for a finished score-reading app themed "DYNAMIC", deployed at dynamic.oke.jp, publishing `public/` only. The Horn II reading was redone in this session: each source page was transcribed by one Claude subagent (pitch, accidentals, cue exclusion), then rhythm/timing and per-bar numbers were added by the same subagents, with automated consistency checks (`check_rhythm.py`, `validate_reader.py`).
- **Decision:** Serve a static reader at `public/reader/` fed by generated JSON per part. System images are cropped, cleaned derivatives embedded in the JSON (no page scans, no source PDF). The landing page `public/index.html` (generated by `tools/build_fuyomi_catalog.py`) links the reader first and keeps the existing Fuyomi catalog under a collapsible section.
- **Playback:** The owner explicitly requested playback for the new Horn II reading. The reader therefore offers synthesized playback while showing the reading's status ("independent audit not yet done") and limitations. The existing fail-closed flag in `project/dvorak/symphony-no-8/horn-ii/project.json` (which governs the older Fuyomi artifacts) is left unchanged; reconciling the two Horn II readings is follow-up work.
- **Known disagreement to resolve:** the earlier independent audit states movement III has a Horn bass-clef section at system 6; the new reading treats bars 168–179 there as a printed timpani cue (label "Timp.", whole-bar rests in the horn voice).
- **Consequences:** Regeneration needs the source PDF locally (`build_reader.py --pdf`). Reader data must pass `tools/dynamic/validate_reader.py`.
